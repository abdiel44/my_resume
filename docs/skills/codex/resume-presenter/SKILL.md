# Resume Presenter

Use this skill when the user wants to explain, demo, or teach resume versioning to students or professionals.

## Presentation Goals

- Make the workflow practical and easy to copy.
- Show why Git helps with resumes without assuming the audience is already expert.
- Use sanitized examples that do not expose private contact details, application history, employer secrets, or client information.
- Prefer simple commands and visible before/after moments.

## Demo Ingredients

Useful demo pieces:

- A messy file-name example such as `Resume_Final_Final.pdf`.
- A clean Git repo with `resume.tex`, `README.md`, `scripts/build.ps1`, and `dist/resume.pdf`.
- Branch examples for `internship`, `research`, `grad-school`, and `role/company-position`.
- Tag examples for submitted versions.
- A short diff showing targeted resume edits.

## Privacy Checklist

Before sharing:

- Remove private phone numbers and personal email addresses.
- Remove confidential client, employer, or internal project details.
- Use a demo branch or fabricated opportunity names.
- Avoid exposing private application branches or tags.
